# DAO Rus

DAO Rus — репозиторий цифрового движка и базовых организационных документов ДАО Русь.

Цель проекта — создать инфраструктуру для децентрализованной автономной организации, в которой цифровые инструменты помогают участникам обсуждать предложения, принимать решения, координировать проекты, учитывать активность и репутацию и сохранять историю организации.

Моральный кодекс (Базовые принципы) ДАО Русь:

1. Не нападай первым.
2. Стой за свою свободу, уважай чужую; границы свобод определяются договором и вече.
3. Народовластие.

## Статус проекта

Проект находится на ранней экспериментальной стадии.

Текущая задача — определить минимальную модель организации и на её основе постепенно создать работающий прототип движка.

Разработка строится по принципу:

**гипотеза → реализация → практика → наблюдение → корректировка → новая версия**

Поэтому документы и программная архитектура версий `0.x` считаются рабочими и могут существенно изменяться.

## Общая архитектурная идея

Telegram и сайт не должны существовать как две независимые организации.

Они рассматриваются как интерфейсы к единому цифровому ядру ДАО.

```text
Telegram ─┐
          │
Сайт ─────┼── DAO Core ── база данных
          │
ИИ ───────┘
```

В ядре должны храниться основные сущности и состояние организации:

* участники;
* роли;
* активность;
* репутационные профили;
* предложения;
* решения;
* проекты;
* задачи;
* история значимых событий.

Telegram при этом может оставаться главным пространством повседневного общения.

## Репутация

Репутация участника не должна сводиться к единому социальному рейтингу.

В первоначальной модели предполагаются несколько независимых профилей:

* **активность** — степень участия в жизни ДАО;
* **отзывы** — оценки участника другими участниками;
* **коммуникабельность** — реакция сообщества на взаимодействие с человеком, включая лайки, дизлайки и другие сигналы.

Методики расчёта этих показателей будут определяться и корректироваться по результатам практического использования.

## История и прозрачность

Значимые действия внутри ДАО должны оставлять прослеживаемую историю.

Например:

* вступление участника;
* создание предложения;
* изменение его редакции;
* начало голосования;
* подача голосов;
* принятие решения;
* создание проекта;
* выполнение задачи.

Старые состояния и решения не должны незаметно переписываться задним числом.

Git используется для сохранения истории развития документов и программного кода.

## Версии

Основные документы имеют номер версии.

Например:

```text
0.1
0.2
0.3
...
1.0
```

Версии `0.x` являются экспериментальными.

Версия `1.0` будет означать, что базовая модель прошла достаточную практическую проверку и может считаться относительно стабильной.

Исторические версии должны оставаться доступными через историю Git и теги.

Пример:

```text
ontology-v0.1
ontology-v0.2
```

## Как предлагать изменения

На раннем этапе изменения могут обсуждаться в рабочих каналах ДАО и после согласования вноситься в репозиторий.

По мере развития проекта предполагается перейти к более формальной процедуре:

**предложение → обсуждение → решение → изменение документа или кода**

Таким образом, сам движок ДАО со временем должен стать инструментом собственного развития организации.

## Текущий приоритет

Первый этап проекта:

1. сформировать онтологию ДАО Русь;
2. описать минимальные организационные процессы;
3. спроектировать единое ядро данных;
4. связать его с Telegram и сайтом;
5. запустить минимальный рабочий прототип;
6. корректировать модель на основании реальной практики.

Главный принцип разработки: сначала создавать минимально достаточные механизмы и проверять их на практике, а не пытаться заранее спроектировать окончательную систему.
