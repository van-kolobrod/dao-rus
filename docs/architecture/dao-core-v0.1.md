# Архитектура DAO Core

**Версия 0.1**
**Дата:** 21 августа 2026 года
**Статус:** рабочий документ

## 1. Назначение

DAO Core — собственное цифровое ядро ДАО Русь.

Его задача — хранить состояние организации и обеспечивать работу её основных механизмов независимо от конкретных внешних интерфейсов.

Telegram, сайт и другие сервисы рассматриваются как интерфейсы к DAO Core, но не как место существования самой организации.

Базовая схема:

```text
Telegram ───────┐
                │
Web ────────────┼── DAO Core ── PostgreSQL
                │       │
AI ─────────────┘       └── журнал событий
```

## 2. Принцип разработки

Версия 0.1 создаётся как минимальный рабочий прототип.

Основной цикл разработки:

**гипотеза → реализация → практика → наблюдение → корректировка**

Архитектура не должна заранее пытаться реализовать окончательное устройство ДАО.

Приоритет:

* простота;
* прозрачность;
* возможность быстро менять модель;
* сохранение данных и истории;
* независимость от конкретного интерфейса или внешнего сервиса.

## 3. Технический подход

На первом этапе DAO Core создаётся как **модульный монолит**.

Предварительный стек:

* TypeScript;
* Next.js;
* PostgreSQL;
* Docker;
* OpenAI API;
* Telegram API.

Не используются без отдельной необходимости:

* микросервисы;
* Kubernetes;
* блокчейн;
* сложная распределённая инфраструктура.

## 4. Основные модули

### Identity

Отвечает за идентичность участников.

Первоначально:

* внутренний ID участника;
* связь с Telegram;
* имя;
* статус членства;
* дата регистрации;
* роли.

Telegram ID является внешним идентификатором, но не заменяет внутренний ID DAO Core.

### Reputation

Хранит и рассчитывает независимые репутационные профили:

* активность;
* отзывы;
* коммуникабельность.

В версии 0.1 они не сводятся к единому рейтингу.

Формулы расчёта могут изменяться по результатам практики.

### Governance

Отвечает за формальные организационные процессы.

Первоначально:

* предложения;
* их состояния;
* решения;
* связь предложения с решением.

Механизмы вече и голосований могут быть добавлены отдельным этапом.

### Events

Фиксирует значимые действия и изменения состояния системы.

Например:

```text
participant.created
participant.logged_in
proposal.created
proposal.updated
decision.created
review.created
```

Журнал событий является основой:

* истории организации;
* аудита;
* расчёта активности;
* будущей ИИ-памяти.

### AI

Отвечает за взаимодействие DAO Core с языковыми моделями.

Первоначальный провайдер — OpenAI.

Первые функции:

* ответы по документам и данным ДАО;
* резюмирование обсуждений;
* помощь при формулировании предложений.

ИИ не является источником политических решений и не должен самостоятельно определять права участников.

## 5. База данных

DAO Core использует собственную PostgreSQL.

База данных является основным структурированным источником состояния организации.

В первоначальной версии предполагаются сущности:

```text
participants
external_identities
roles
reputation
reviews
proposals
decisions
events
```

Точная схема определяется при создании первого прототипа.

## 6. Telegram

Telegram остаётся основной средой повседневного общения ДАО.

DAO Core не должен требовать от участников перехода из Telegram в отдельный форум.

Предполагаемая интеграция:

```text
Telegram
   │
   ├── вход через Telegram
   ├── DAO-бот
   └── Telegram Mini App
            │
            ▼
        DAO Core
```

Существующий `tg-oauth-bridge` сохраняется как legacy-компонент старой Discourse-инфраструктуры.

В DAO Core Telegram-аутентификация реализуется непосредственно.

## 7. Web

`daorus.org` должен постепенно стать веб-интерфейсом DAO Core.

Первоначальные страницы:

```text
/profile
/people
/proposals
/decisions
```

На первом этапе существующий Discourse может продолжать работать параллельно.

После появления рабочего DAO Core и сохранения необходимых данных дальнейшая роль Discourse определяется отдельно.

## 8. ИИ

ИИ подключается через серверную часть DAO Core.

API-ключи никогда не передаются в браузер, Telegram Mini App или публичный репозиторий.

Первоначальная схема:

```text
Пользователь
     ↓
DAO Core
     ↓
AI-модуль
     ↓
OpenAI API
     ↓
GPT-5.6
```

В дальнейшем AI-модуль может превратиться в отдельный AI Gateway и поддерживать несколько моделей и провайдеров.

## 9. Безопасность

Базовые требования версии 0.1:

* секреты хранятся только на сервере;
* `.env` не попадает в Git;
* значимые действия фиксируются;
* ИИ не получает прямого доступа к PostgreSQL;
* права доступа проверяются DAO Core;
* перед крупными изменениями инфраструктуры создаются резервные копии или snapshots;
* старые данные не удаляются до проверки успешности миграции.

## 10. Первый вертикальный срез

Первая версия должна реализовать только один законченный пользовательский сценарий:

```text
Пользователь открывает daorus.org
          ↓
«Войти через Telegram»
          ↓
Telegram подтверждает идентичность
          ↓
DAO Core ищет участника
          ↓
если участника нет — создаёт
          ↓
открывает профиль
```

Первоначальный профиль:

```text
Имя
Telegram
Статус
Дата регистрации

Активность: —
Отзывы: —
Коммуникабельность: —
```

Главный результат этого этапа:

**появляется единая сущность Participant, принадлежащая DAO Core, а не Telegram или Discourse.**

## 11. Следующие этапы

После успешного первого вертикального среза:

1. журнал событий;
2. сбор активности;
3. отзывы;
4. коммуникабельность;
5. предложения;
6. решения;
7. Telegram-бот;
8. ИИ-память и «Спросить ДАО»;
9. проекты и задачи;
10. дальнейшее развитие механизмов народовластия.

## 12. Критерий готовности версии 0.1

DAO Core v0.1 считается работающим прототипом, если:

* пользователь может войти через Telegram;
* система создаёт и сохраняет собственного участника;
* участник повторно распознаётся при входе;
* профиль хранится в PostgreSQL;
* основные действия фиксируются в журнале событий;
* приложение можно безопасно обновлять без потери данных.

После достижения этого состояния архитектура пересматривается на основании практического опыта.
